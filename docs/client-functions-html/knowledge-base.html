База знаний (KB), общий доступ и работа с документами

Документы проекта, вложенные страницы, комментарии, экспорт и публичные ссылки для команды и клиентов.

Где находится

  • Список KB в настройках: `/settings?tab=kb`
  • Редактор документа: `/kb/[documentId]`
  • Публичная ссылка на документ: `/kb/share/[token]`
/kb/[documentId] /kb/share/[token]
Быстрый переход по странице
1. База знаний во вкладке настроек 2. Страница документа (`/kb/[documentId]`) 3. Публичный доступ к документу (`/kb/share/[token]`) 4. Связь KB с другими модулями

1. База знаний во вкладке настроек

KB открывается из `/settings?tab=kb` и показывает дерево документов проекта.

Дерево документов

Простыми словами: Документы отображаются в древовидной структуре с вложенными страницами.

Зачем это нужно: Удобно строить структуру базы знаний как в wiki.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Новый документ

Простыми словами: Создание корневого документа из списка KB.

Зачем это нужно: Быстрый старт новой инструкции/регламента.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Новая вложенная страница

Простыми словами: Можно создать дочернюю страницу прямо из строки документа.

Зачем это нужно: Легко строить многоуровневые материалы.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Архив/восстановление

Простыми словами: Документы можно архивировать и возвращать из архива.

Зачем это нужно: Поддерживает порядок без безвозвратного удаления.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Режим просмотра архива

Простыми словами: Переключатель «Архив» показывает архивированные документы.

Зачем это нужно: Помогает безопасно управлять жизненным циклом материалов.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Переход в документ

Простыми словами: Кнопка «Открыть» ведёт в редактор конкретного документа `/kb/[documentId]`.

Зачем это нужно: Основной путь к редактированию содержимого.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

2. Страница документа (`/kb/[documentId]`)

Основной редактор документа с верхней панелью действий и Tiptap-редактором.

Редактирование заголовка и иконки

Простыми словами: Название и иконка документа редактируются прямо в шапке.

Зачем это нужно: Упрощает организацию и визуальную навигацию по KB.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Tiptap-редактор документа

Простыми словами: Основной контент документа редактируется в rich-text-редакторе.

Зачем это нужно: Подходит для инструкций, регламентов, шаблонов и заметок.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Автосохранение контента

Простыми словами: Редактор сохраняет изменения автоматически с заданным интервалом.

Зачем это нужно: Снижает риск потери текста.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Создание вложенных страниц из редактора

Простыми словами: Из редактора можно создавать дочерние страницы и сразу видеть их в списке.

Зачем это нужно: Ускоряет структурирование материалов во время написания.

Пример из жизни: Например, новый сотрудник открывает одну страницу и за 10 минут понимает, как вести клиента.

Комментарии (панель справа)

Простыми словами: Можно включить/выключить панель комментариев к документу.

Зачем это нужно: Удобно для ревью и совместной работы.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Экспорт документа

Простыми словами: Отдельная кнопка `ExportButton` помогает выгружать документ.

Зачем это нужно: Полезно для передачи материалов вне системы.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Создание публичной ссылки

Простыми словами: `ShareButton` создаёт ссылку на публичный просмотр документа.

Зачем это нужно: Можно безопасно делиться материалом с клиентом или подрядчиком.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

Дублирование документа

Простыми словами: Документ можно копировать (включая/без вложенных страниц по сценарию кнопки).

Зачем это нужно: Быстрое создание шаблонов на основе готового материала.

Пример из жизни: Например, вы сделали отдельный шаблон для продающих постов и потом запускаете генерацию по нему каждую неделю.

Архивирование документа

Простыми словами: Документ можно архивировать прямо из меню действий.

Зачем это нужно: Поддерживает порядок в KB.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Вложенные страницы внизу документа

Простыми словами: Ниже редактора показывается список дочерних страниц с переходами.

Зачем это нужно: Прозрачная навигация по разделу знаний.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

3. Публичный доступ к документу (`/kb/share/[token]`)

Публичная read-only страница, открываемая по share-токену.

Публичный просмотр документа

Простыми словами: Документ открывается по токену без входа в систему.

Зачем это нужно: Удобно отправлять инструкции клиенту и подрядчикам.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

Проверка доступности ссылки

Простыми словами: Если ссылка недоступна/истекла, показывается понятное сообщение.

Зачем это нужно: Пользователь понимает причину, а не видит пустую ошибку.

Пример из жизни: Например, новый сотрудник открывает одну страницу и за 10 минут понимает, как вести клиента.

Отдельные метаданные для шаринга

Простыми словами: Страница формирует заголовок документа в метаданных по содержимому share.

Зачем это нужно: Улучшает пользовательский опыт при открытии ссылки.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

4. Связь KB с другими модулями

KB используется не только как хранилище документов, но и как база для клиентских и AI-сценариев.

Тип документа «product»

Простыми словами: Документ может быть отмечен как продуктовый (показывается бейдж типа).

Зачем это нужно: Помогает использовать KB как часть продуктовой выдачи.

Пример из жизни: Например, вы визуально раскладываете core-продукт, допродажи и модули, чтобы собрать понятную линейку.

Выдача цифровых продуктов через публичную страницу клиента

Простыми словами: Ссылки на документы KB могут использоваться как цифровая выдача после оплаты на `/c/[client_id]`.

Зачем это нужно: KB становится хранилищем выдаваемых материалов.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

RAG-чат в настройках

Простыми словами: Документы KB используются как источник ответов в RAG-чат-виджете на странице настроек.

Зачем это нужно: Команда получает быстрый поиск по знаниям.

Пример из жизни: Например, вы один раз настраиваете часовой пояс и соцаккаунты, чтобы публикации и встречи шли в правильное время.
