1. Публичная страница клиента (`/c/[client_id]`)

Публичная страница собирается из включаемых блоков и может использоваться как мини-кабинет клиента.

Шапка клиента

Простыми словами: Отображает имя/бренд и общий контекст страницы клиента.

Зачем это нужно: Создаёт персонализированную точку входа для клиента.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

Блок продукта

Простыми словами: Показывает выбранный продукт, описание и кнопку покупки (если включено в шаблоне страницы).

Зачем это нужно: Клиент видит актуальное коммерческое предложение.

Пример из жизни: Например, вы сделали отдельный шаблон для продающих постов и потом запускаете генерацию по нему каждую неделю.

Текстовый блок (custom content)

Простыми словами: Владелец страницы может вставлять произвольный rich-text контент.

Зачем это нужно: Подходит для инструкций, приветствия, условий и офферов.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Блок записи на встречу

Простыми словами: Показывает доступные слоты и помогает записаться/перенести встречу.

Зачем это нужно: Клиент может сам выбрать удобное время.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Блок запланированных встреч

Простыми словами: Отображает список уже назначенных встреч клиента.

Зачем это нужно: Клиент видит свои будущие встречи в одном месте.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Блок списка покупок

Простыми словами: Показывает оплаченные продукты и статус выдачи цифровых материалов.

Зачем это нужно: Клиенту не нужно писать менеджеру, чтобы найти доступы.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

Блок рефералов

Простыми словами: Показывает реферальную ссылку, количество приглашённых и статус приглашений.

Зачем это нужно: Поддерживает партнёрскую механику для клиента.

Пример из жизни: Например, клиент поделился своей ссылкой с другом и потом видит в кабинете, что приглашение зарегистрировалось.

2. Авторизация контакта на публичной странице

Часть функций на публичной странице доступна только после входа как контакт через Telegram/VK.

Вход как контакт

Простыми словами: На странице можно войти как контакт через Telegram или VK.

Зачем это нужно: Открывает функции записи, покупок и рефералов.

Пример из жизни: Например, клиент поделился своей ссылкой с другом и потом видит в кабинете, что приглашение зарегистрировалось.

Режим просмотра без входа

Простыми словами: Без авторизации клиент видит только доступные для просмотра блоки и слоты без действия записи/покупки.

Зачем это нужно: Безопасный публичный просмотр страницы.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Определение привязанного контакта

Простыми словами: После входа страница связывается с CRM-контактом и показывает персональные данные (покупки/встречи).

Зачем это нужно: Получается персональный клиентский портал без отдельного личного кабинета.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

3. Запись на встречу и перенос

Сценарий self-service записи клиента на доступные слоты.

Просмотр свободных слотов

Простыми словами: Показываются доступные окна времени, подготовленные владельцем страницы/CRM.

Зачем это нужно: Клиент сам выбирает удобное время.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Запись на слот

Простыми словами: После входа как контакт клиент может выбрать слот и создать запись на встречу.

Зачем это нужно: Снижает нагрузку на менеджера при согласовании времени.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Перенос встречи

Простыми словами: Если встреча уже назначена, клиент может перейти в режим переноса и выбрать новый слот.

Зачем это нужно: Самообслуживание при изменении расписания.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Проверка занятости слота

Простыми словами: Сервис проверяет, занят ли слот, и показывает понятную ошибку при конфликте.

Зачем это нужно: Снижает риск двойного бронирования.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

4. Покупка продукта и выдача цифрового материала

Публичная страница поддерживает покупку продукта и выдачу цифрового контента после оплаты.

Инициация покупки

Простыми словами: Кнопка «Купить» запускает создание оплаты для выбранного продукта.

Зачем это нужно: Клиент может купить продукт напрямую со своей страницы.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Проверка статуса оплаты

Простыми словами: Страница отслеживает статус платежа и показывает сообщение о результате.

Зачем это нужно: Клиент понимает, прошла ли оплата и что делать дальше.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Переход к оплате

Простыми словами: Сервис направляет клиента на платёжную ссылку/страницу подтверждения оплаты.

Зачем это нужно: Фактическая оплата происходит в платёжном провайдере.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Выдача цифрового продукта

Простыми словами: После успешной оплаты показывается ссылка на цифровой материал (если готова выдача).

Зачем это нужно: Клиент получает доступ сразу после оплаты.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Сообщение о задержке выдачи

Простыми словами: Если выдача ещё не готова, сервис показывает понятное сообщение вместо «пустого» состояния.

Зачем это нужно: Снижает количество вопросов в поддержку.

Пример из жизни: Например, клиент заходит по ссылке, оплачивает продукт и сразу получает доступ к материалу.

8. Маршруты оплаты и возврата

Служебные клиентские маршруты помогают корректно возвращать пользователя в экран оплаты.

`/pay`

Простыми словами: Маршрут-переход, который отправляет пользователя в раздел оплаты настроек (`/settings?tab=payment`).

Зачем это нужно: Единая точка входа в оплату из внешних ссылок.

Пример из жизни: Например, вы отправляете коллеге ссылку сразу на нужную вкладку, а не объясняете по шагам, куда нажимать.

`/pay/success`

Простыми словами: После успешной оплаты маршрут возвращает в настройки оплаты и передаёт `payment_id`, если он есть.

Зачем это нужно: Пользователь видит статус платежа в интерфейсе системы.

Пример из жизни: Например, вы отправляете коллеге ссылку сразу на нужную вкладку, а не объясняете по шагам, куда нажимать.
