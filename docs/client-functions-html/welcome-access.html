Вход, старт и навигация

Как пользователь входит в систему, что видит первым и как перемещается между разделами.

Где находится

  • Публичный вход: `/login`
  • Callback VK: `/auth/vk/callback`
  • Старт после входа: `/welcome`
  • Публичный лендинг: `/`

1. Авторизация и доступ

Система поддерживает несколько сценариев входа для сотрудников и контактов клиентов.

Вход через Telegram

Простыми словами: Пользователь авторизуется через Telegram-виджет/бот из страницы `/login`.

Зачем это нужно: Быстрый вход в личный кабинет без отдельного пароля.

Пример из жизни: Например, вы собираете цепочку приветствия: сообщение → кнопки → напоминание через 1 день.

Вход через VK

Простыми словами: Авторизация через ВКонтакте запускается с `/login`, а обратный переход обрабатывается на `/auth/vk/callback`.

Зачем это нужно: Помогает использовать VK как способ входа и привязки аккаунта.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

Режим входа контакта клиента

Простыми словами: Страница `/login` умеет режим «Войти как контакт» (через `tenant_id`).

Зачем это нужно: Контакт получает доступ к клиентской странице для записи, покупок и рефералов.

Пример из жизни: Например, клиент поделился своей ссылкой с другом и потом видит в кабинете, что приглашение зарегистрировалось.

Обработка VK callback

Простыми словами: После авторизации VK сервис автоматически завершает вход/привязку и возвращает пользователя в нужный раздел.

Зачем это нужно: Убирает ручные шаги после авторизации.

Пример из жизни: Например, сотрудник заходит через Telegram за 1 минуту и сразу попадает на главный экран с нужными разделами.

Публичные страницы без входа

Простыми словами: Без авторизации доступны маркетинговый лендинг, login, публичная страница клиента и публичные ссылки KB.

Зачем это нужно: Клиент может просматривать и переходить по ссылкам без доступа в кабинет.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

2. Стартовый экран (Welcome)

После входа пользователь попадает на экран с двумя ветками: маркетинг/SEO и управление клиентами.

Обзор двух веток работы

Простыми словами: Стартовая страница показывает блоки «маркетинг/SEO» и «управление клиентами».

Зачем это нужно: Пользователь сразу понимает, где искать нужный сценарий.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Быстрые переходы по шагам

Простыми словами: Карточки на welcome ведут в аналитику, SEO, посты, клиентов, настройки и другие разделы.

Зачем это нужно: Сокращает путь до ключевых функций системы.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Счётчики выполненных AI-действий

Простыми словами: На welcome отображаются счётчики событий генерации/аналитики (посты, Wordstat, SEO-группы и др.).

Зачем это нужно: Помогает быстро оценить прогресс работ по проекту.

Пример из жизни: Например, вы продаёте кухни и хотите понять, что люди ищут чаще: «кухня на заказ» или «кухня под ключ».

Навигация по клиентским сценариям

Простыми словами: Отдельные карточки ведут к встречам, чат-цепочкам, оплатам и сбору обратной связи.

Зачем это нужно: Удобно для менеджера/оператора в ежедневной работе.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

3. Меню и навигация по системе

Навигация единая для desktop и mobile, с адаптацией под публичные/приватные маршруты.

Боковое меню разделов

Простыми словами: Основные разделы: Приветствие, Аналитика, Посты, SEO, Статьи, Продукты, Клиенты, Настройки.

Зачем это нужно: Даёт постоянный доступ к основным функциям системы.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Мобильное меню

Простыми словами: На мобильных устройствах нужно для выезжающее меню со списком разделов.

Зачем это нужно: Сохраняет доступность функций на телефоне/планшете.

Пример из жизни: Например, вы делаете это один раз в интерфейсе, и дальше команда тратит меньше времени на ручную работу.

Подсветка активного раздела

Простыми словами: Текущий раздел автоматически подсвечивается в меню.

Зачем это нужно: Снижает вероятность ошибок навигации.

Пример из жизни: Например, вы делаете это один раз в интерфейсе, и дальше команда тратит меньше времени на ручную работу.

Выход из системы

Простыми словами: Кнопка «Выйти» завершает сессию и возвращает пользователя на публичный вход.

Зачем это нужно: Нужна для безопасной работы на общих устройствах.

Пример из жизни: Например, сотрудник заходит через Telegram за 1 минуту и сразу попадает на главный экран с нужными разделами.

4. Роли и ограничения редактирования

Во многих разделах система различает просмотр и редактирование (через проверку прав роли).

Режим просмотра

Простыми словами: Пользователь без прав видит данные, но не может запускать генерацию или менять настройки.

Зачем это нужно: Безопасный доступ для наблюдателей/ассистентов.

Пример из жизни: Например, вы один раз настраиваете часовой пояс и соцаккаунты, чтобы публикации и встречи шли в правильное время.

Режим редактирования

Простыми словами: Владелец/редактор может запускать AI-процессы, создавать записи, изменять настройки и удалять элементы.

Зачем это нужно: Полный рабочий режим для операционной команды.

Пример из жизни: Например, вы один раз настраиваете часовой пояс и соцаккаунты, чтобы публикации и встречи шли в правильное время.

Подсказки при отсутствии прав

Простыми словами: В разделах показываются сообщения о нехватке прав на запуск/изменение данных.

Зачем это нужно: Пользователь понимает, почему действие недоступно.

Пример из жизни: Например, вы делаете это один раз в интерфейсе, и дальше команда тратит меньше времени на ручную работу.
