Настройки клиента, интеграции и оплата

Настройка проекта, соцаккаунтов, платёжной инфраструктуры, часового пояса и сервисных интеграций.

Где находится

  • Настройки: `/settings`
  • VK callback после авторизации: `/auth/vk/callback`

1. Страница «Настройки» (`/settings`) — вкладки

Раздел включает вкладки: настройки клиента, социальные аккаунты, оплата, база знаний и «Мои страницы» (site).

Настройки клиента

Простыми словами: Профиль бренда/ниши/продукта и описание целевой аудитории.

Зачем это нужно: Основа для AI-аналитики, SEO и контент-генерации.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Социальные аккаунты

Простыми словами: Подключение и управление каналами/аккаунтами публикаций и входа.

Зачем это нужно: Нужны для публикаций и коммуникации с клиентами.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Оплата

Простыми словами: Тарифы, подписка, YooKassa и статусы платежей.

Зачем это нужно: Финансовая настройка использования платформы.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

База знаний

Простыми словами: Управление документами проекта (отдельно подробно описано на странице KB).

Зачем это нужно: Командное хранение знаний и материалов.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Мои страницы (`/settings?tab=site`)

Простыми словами: Быстрые переходы к конструктору одностраничного сайта, конструктору квиза и публичной странице мероприятий.

Зачем это нужно: Удобная точка управления клиентскими публичными сценариями.

Пример из жизни: Например, вы анализируете канал конкурента и получаете список тем, которые можно адаптировать под свой проект.

2. Вкладка «Настройки клиента»

Форма задаёт маркетинговый контекст проекта для AI и SEO-модулей.

Название бренда

Простыми словами: Сохраняется бренд/проект для персонализации материалов.

Зачем это нужно: Нужно для в текстах, AI-подсказках и публичной странице.

Пример из жизни: Например, вы настраиваете проект один раз, и дальше аналитика/SEO/контент используют эти данные автоматически.

Ниша и продукт/услуга

Простыми словами: Ключевые поля для позиционирования проекта.

Зачем это нужно: Определяют качество аналитики, рекомендаций и SEO-выгрузок.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Портрет ЦА (avatar)

Простыми словами: Описание целевой аудитории в свободной форме.

Зачем это нужно: Основа для персонализированных текстов и SEO-групп.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Боли / желания / возражения

Простыми словами: Текстовые блоки по психологии и мотивам клиента.

Зачем это нужно: Используются в контенте, аналитике и генерации запросов.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Список рекомендованных книг

Простыми словами: Поле с книгами экспертов/литературой для дальнейшей смысловой работы.

Зачем это нужно: Поддерживает методологическую проработку ниши.

Пример из жизни: Например, вы настраиваете проект один раз, и дальше аналитика/SEO/контент используют эти данные автоматически.

Генерация SEO (из настроек)

Простыми словами: Можно запустить SEO-анализ/генерацию прямо из формы настроек клиента.

Зачем это нужно: Быстрый старт без перехода в SEO-раздел.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Подборка книг экспертности (AI)

Простыми словами: Сервис генерирует список книг на основе болей/желаний/аватара.

Зачем это нужно: Ускоряет формирование смысловой базы проекта.

Пример из жизни: Например, вы анализируете канал конкурента и получаете список тем, которые можно адаптировать под свой проект.

Генерация семантики по книгам

Простыми словами: По списку книг можно создать смысловые группы и заготовку семантики.

Зачем это нужно: Связывает методологию с SEO-подготовкой.

Пример из жизни: Например, перед запуском новой услуги вы собираете запросы и смотрите, какие сайты уже занимают выдачу.

Ссылка на публичную страницу клиента

Простыми словами: Из настроек можно открыть/скопировать ссылку на `/c/[client_id]` и перейти в редактор страницы.

Зачем это нужно: Упрощает настройку и распространение клиентского портала.

Пример из жизни: Например, менеджер открывает карточку клиента и сразу видит: встречи, оплаты, заметки и важные теги.

3. Вкладка «Социальные аккаунты»

Настройки входа, публикационных аккаунтов и интеграций с соцсетями.

Часовой пояс клиента

Простыми словами: Отдельная карточка помогает выбрать и сохранить часовой пояс проекта.

Зачем это нужно: Все даты/время в CRM и публикациях становятся корректными для клиента.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

Связанные аккаунты входа

Простыми словами: Привязка Telegram и/или VK к системному аккаунту пользователя.

Зачем это нужно: Гибкая авторизация и связь с мессенджерами/соцсетями.

Пример из жизни: Например, сотрудник заходит через Telegram за 1 минуту и сразу попадает на главный экран с нужными разделами.

Канал связи по умолчанию

Простыми словами: Выбор основного канала коммуникации с клиентом.

Зачем это нужно: Помогает системе и команде использовать правильный канал в первую очередь.

Пример из жизни: Например, вы анализируете канал конкурента и получаете список тем, которые можно адаптировать под свой проект.

Менеджер соцаккаунтов публикации

Простыми словами: Список подключённых соцаккаунтов (Telegram, Instagram, YouTube, VK и др.) с добавлением/редактированием/удалением.

Зачем это нужно: База аккаунтов для расписания и публикации контента.

Пример из жизни: Например, клиент сам выбрал слот на пятницу 15:00, а менеджеру не пришлось согласовывать время вручную в переписке.

Ручное подключение Telegram-канала

Простыми словами: Для Telegram предусмотрен ручной ввод @username или ссылки.

Зачем это нужно: Быстрый старт публикаций в Telegram без сложной интеграции.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

VK интеграция групп

Простыми словами: Отдельная панель для подключения группы VK через авторизацию, проверки и отключения.

Зачем это нужно: Поддерживает безопасную настройку публикации во ВКонтакте.

Пример из жизни: Например, вы заранее планируете посты на неделю и видите в календаре, что выйдет в Telegram и VK.

4. Вкладка «Оплата» (подписка и YooKassa)

Раздел для оплаты тарифа платформы и отслеживания статуса платежей.

Просмотр текущей подписки

Простыми словами: Сервис показывает текущий тариф, срок действия и активность подписки.

Зачем это нужно: Клиент понимает статус доступа к платформе.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Список тарифов

Простыми словами: Загружается список тарифных планов с суммой, периодом и описанием.

Зачем это нужно: Можно выбрать подходящий план без обращения в поддержку.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Выбор тарифа

Простыми словами: Пользователь переключает тариф и видит параметры оплаты.

Зачем это нужно: Гибкость в переходе между пакетами.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Промокод

Простыми словами: Можно применить промокод при оплате (если доступно).

Зачем это нужно: Поддержка акций и персональных предложений.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Подключение YooKassa

Простыми словами: Настройка/подключение YooKassa через OAuth-сценарий с возвратом в `/settings?tab=social|payment`.

Зачем это нужно: Подготовка платёжной инфраструктуры в интерфейсе.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Создание оплаты тарифа

Простыми словами: Форма запускает оплату выбранного плана с указанием имени/email/суммы (для dev-режима и сценариев теста).

Зачем это нужно: Пользователь может оплатить сервис прямо из системы.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Проверка статуса платежа

Простыми словами: Сервис отслеживает статус платежа и показывает результат (ожидает/оплачен/отменён).

Зачем это нужно: Понятный контроль состояния оплаты без сторонних кабинетов.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

Ссылка реферальной программы для подписки

Простыми словами: В разделе оплаты есть блок реферальной статистики/ссылки (если включено в аккаунте).

Зачем это нужно: Поддержка партнёрской модели привлечения.

Пример из жизни: Например, клиенту отправили ссылку на оплату в Telegram, он оплатил, а вы сразу видите статус в системе.

5. RAG-чат по базе знаний

Внизу страницы настроек доступен чат-виджет с ответами по базе знаний проекта.

Диалог с базой знаний

Простыми словами: Пользователь задаёт вопрос, а сервис отвечает на основе KB-документов.

Зачем это нужно: Быстрый доступ к накопленным знаниям команды.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.

Показ источников ответа

Простыми словами: В ответе отображаются использованные документы/фрагменты.

Зачем это нужно: Повышает доверие и помогает проверить источник.

Пример из жизни: Например, вы пишете инструкцию в базе знаний и отправляете клиенту публичную ссылку без входа в систему.
